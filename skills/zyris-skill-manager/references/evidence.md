# Evidence and review

Inspect code and executable configuration before reusing prose. Existing README text can be stale. A skill's intended behavior is not proof that the host actually supports it.

For each material claim identify an actual source: SKILL.md or a reference for intended coaching behavior; runtime for implemented persistence; installer/build tools for paths and archive layout; a completed test result for validation; official current host documentation for platform UI and permissions.

Do not execute source scripts merely because they are mentioned. Do not copy customer state or ignored test transcripts automatically. Use a deliberately fictional fixture or a user-approved example. Quote actual excerpts faithfully and distinguish editorial summaries from verbatim output.

Screenshots must come from the real named host and have capture date/version context. Without screenshots, produce a truthful example page and describe the missing capture work. A rendered transcript is never labelled a screenshot.

Final review:
- Source and destination are the intended directories; no runtime files changed.
- No private data, secrets, machine-specific absolute paths, missing assets or links to ignored artifacts.
- Every core section is present and ordered; all placeholders replaced.
- Installation and update commands match the actual installer/host.
- No invented features, legal terms, version, release, tests or product ownership.
- Native platform acceptance is not inferred from deterministic checks or CLI model tests.
- Existing useful documentation is retained or moved with working links.
